# Домонетка

Приложение на Python 3.10+ и SQLite. Основной режим использует стандартную библиотеку; для входа OpsVault устанавливается клиент opsvault-sso 0.1.2 в отдельное окружение.

Опубликовано: https://dop.afriro.online/ — страница, https://dop.afriro.online/admin — управление. Сервер 176.100.37.104, каталог `/opt/domonetka`, отдельный пользователь и systemd-сервис `domonetka`, локальный порт 8097. Пароль публичной админки выдан отдельно; он хранится на сервере в `/etc/domonetka.env` с правами 600. Локальный пароль ниже не работает на публичном сайте.

## Запуск

В папке проекта выполните `python server.py` (или `./start.ps1`).

- Страница офферов: http://127.0.0.1:8080/
- Админка: http://127.0.0.1:8080/admin
- Локальный логин: `admin`, первоначальный пароль: `admin-local-2026`

Пароль можно заменить через переменную окружения `ADMIN_PASSWORD`. Порт — через `PORT`. Сервер слушает только 127.0.0.1. Для доступа используйте один и тот же адрес: cookies для localhost и 127.0.0.1 различаются.

## Офферы и варианты

## Потоки

В кабинете выберите поток сверху. «Новый поток» создаёт отдельную домонетку с любым удобным названием и адресом `/s/<slug>`. Полей страны и GEO нет. Адрес состоит из латинских букв, цифр и дефисов; после создания он не меняется, чтобы подключённый код продолжал работать. Поток можно переименовать и поставить на паузу в настройках.

Все прежние офферы и их статистика автоматически принадлежат «Основному потоку» (`/s/main`). Старый адрес `/` продолжает открывать его. В каждом потоке собственные офферы, посетители, события и рейтинг; один браузер может учитываться посетителем нескольких потоков.

«Копировать офферы» позволяет выбрать источник, назначение и один или несколько офферов (до 100 за операцию). Копируются материалы, ссылки и статус активности; варианты создаются заново с независимыми идентификаторами и нулевой статистикой. Исходный оффер и его данные сохраняются. Повторное копирование создаёт ещё одну копию. Загруженные картинки используются совместно, но изменение списка материалов в копии не меняет исходный оффер.

«Получить код» формирует готовый script с точным URL выбранного потока. Вставьте его перед `</body>` на соответствующем лендинге. Ссылка потока также доступна для копирования и проверки в верхней панели админки. Выбор потока сохраняется в браузере админа. Демо-лендинг возвращает в тот поток, из которого пришёл посетитель.

## Пользователи и права

Первоначальная учётная запись — `admin`. На опубликованном сайте её первоначальный пароль остаётся прежним. Первоначальный пароль берётся из ADMIN_PASSWORD только при первой миграции; дальнейшие изменения пароля выполняются через управление пользователями и хранятся в базе.

Администраторы видят все потоки, офферы и статистику, создают и редактируют пользователей, меняют роли, задают новые пароли и отключают учётные записи. Через настройки потока админ может изменить владельца: вместе с потоком переходит доступ ко всем его офферам и статистике. Обычный пользователь получает доступ только к своим потокам и офферам; создание и копирование в чужие потоки запрещено сервером. Публичные страницы потоков остаются открытыми для посетителей.

Пароли хранятся в виде salted PBKDF2-SHA256 (310000 итераций). Хеши не выдаются API. Смена пароля, роли или отключение пользователя завершает его сессии. Последнего активного администратора нельзя отключить или понизить. Отключение пользователя сохраняет его материалы и не выключает публичные потоки автоматически. Админ может отдельно поставить их на паузу. Удаление учётных записей не предусмотрено: используется отключение.

Проверены изоляция аккаунтов, запреты на изменение/удаление/копирование чужих офферов и смену чужого владельца, передача потока администратором, завершение сессий и миграция прежних данных. Перед обновлением создана копия базы и приложения в `/root/domonetka-backup-20261007/before-streams`.

## Материалы офферов

Добавьте ссылку, заголовки, описания и картинки. Каждый текст или URL — отдельная строка. Картинки можно загрузить с компьютера (PNG/JPG/WebP до 5 МБ). Генерируются все уникальные сочетания: 2 заголовка × 2 описания × 3 картинки = 12 вариантов. Максимум 20 материалов каждого типа и 500 сочетаний. Это комбинации материалов баера, не генерация новых текстов или изображений ИИ.

На странице один баннер на оффер. В 80% выборов используется вариант с наибольшим сглаженным рейтингом `(клики + 1)/(показы + 20)`, в 20% — вариант с наименьшим количеством показов. Выбранные баннеры сортируются по рейтингу. Это защищает ранжирование от случайного единственного клика и даёт новым вариантам возможность получить показы. Одинаковые рейтинги сохраняют исходный порядок. Пауза исключает оффер из новых выдач. Уже выданные ссылки работают ещё сутки.

Показ учитывается при видимости минимум 50% баннера в течение секунды. Клик регистрируется сервером перед редиректом; он также подтверждает показ. Повторные события посетителя по варианту за сутки UTC не увеличивают счётчик. Посетитель определяется случайным cookie; это уникальный браузер, а не гарантированно уникальный человек. Общие посетители — браузеры, загрузившие выдачу. Статистика за всё время. CTR — клики/показы. Архивные сочетания сохраняют статистику и возвращаются при повторном добавлении тех же материалов. Удаление оффера удаляет его статистику.

Демонстрационные офферы ведут на локальную тестовую страницу. Их можно удалить в админке. Данные сохраняются в `data/domonetka.sqlite`, картинки в `data/uploads/`; резервируйте всю папку `data` при остановленном сервере.

## Возврат при нажатии «назад»

В админке нажмите «Получить код» и вставьте скрипт перед `</body>` на своём лендинге. `data-domonetka` — полный URL страницы офферов. После переноса на домен замените адреса. Скрипт создаёт дополнительную запись истории текущей страницы и один раз отправляет посетителя на указанный адрес через `location.replace`. URL остаётся прежним. Для сторонних лендингов без доступа к HTML подключение невозможно. Браузер может не отправлять popstate до взаимодействия с документом или пропускать искусственные записи истории; стопроцентная гарантия перехвата системной кнопки «назад» отсутствует. Проверьте Chrome/Safari и встроенные браузеры источника трафика. Обычная навигация на офферы работает без этого скрипта.

## Перенос на сервер

На сервере настроены отдельный systemd-сервис с ограниченными правами и памятью, сильный пароль, HTTPS Caddy/Let's Encrypt, Secure cookies, проверка Origin и ограничение попыток входа (10 за 15 минут с IP прокси). Python слушает только loopback, доступ снаружи идёт через существующий Caddy. Доступно `PUBLIC_ORIGIN=https://dop.afriro.online`; без него используется локальная проверка Origin. Значение PUBLIC_ORIGIN требует отдельного ADMIN_PASSWORD.

Добавлен только файл `/var/lib/docker/volumes/binom_proxy_config/_data/domains/domonetka.caddy` в существующий каталог импорта Binom. Исходные файлы конфигурации сохранены и проверены на неизменность. Резервная копия исходной конфигурации и runtime JSON: `/root/domonetka-backup-20261007`. Caddy применяет изменения без перезапуска контейнеров.

Команды обслуживания: `systemctl status domonetka`, `journalctl -u domonetka -n 100`, `systemctl restart domonetka`. Для ручной резервной копии остановить только `domonetka`, скопировать его папку `data`, затем запустить `domonetka`. WAL SQLite входит в папку data, копировать только один .sqlite во время работы нельзя.

Конфигурации размещены в `deploy/`. Для отката маршрута убрать только добавленный файл `domonetka.caddy`, проверить конфигурацию командой `docker exec binom_proxy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`, затем применить через `caddy reload` с теми же аргументами. Остановить только `domonetka`; другие сервисы не затрагивать.

Это первая рабочая версия. Перед большими объёмами трафика нужны нагрузочная проверка, фильтрация ботов и ограничения частоты публичных событий. Рейтинг основан на кликах, не на выручке или подтверждённых конверсиях.

# Binom v2: локальный первый этап

План и границы реализации: [BINOM_INTEGRATION_PLAN.md](BINOM_INTEGRATION_PLAN.md).
В редакторе баннера появился необязательный ID **кампании** Binom. При его заполнении
переходы получают `dm_source`, `dm_flow`, `dm_offer`, `dm_variant`, `dm_click`.
Эти параметры должны быть настроены в токенах источника трафика Binom.
Раздел **Binom** доступен каждому пользователю: свой адрес трекера, API-ключ и токены
T1–T30. Баннеры наследуют настройки владельца потока. Администратор редактирует
настройки других пользователей через **Пользователи → Binom**. «Свои токены» в редакторе переопределяет
соответствие для отдельного баннера/кампании. Ранее заданные индивидуальные токены
сохраняются. Подсказки показывают Parameter, Placeholder и Name для каждой метки.
Можно сохранить незавершённую настройку; повторяющиеся номера запрещены.
Копирование баннера очищает ID кампании. Журнал `outbound_clicks` хранит каждый
переход отдельно от уникальных кликов CTR, включая кампанию на момент перехода.
Исторические переходы без меток к вариациям не привязываются.

Админка поддерживает диапазон дат и таблицу по дням UTC. Клиент `binom.py` читает
API по заголовку `Api-Key`, предоставляет доступные группировки кампании и страницы
отчёта. Он пока не подключён к фоновому импорту. API-ключ хранится в приватном файле
`data/binom-user-<sha256(user_id)>.json` (600), не возвращается браузеру. При резервном копировании
сохраняйте все файлы `data/binom*.json` вместе с БД. Прежние общие настройки перенесены
первому администратору; другие пользователи не наследуют его ключ. Ключи и пароли не хранятся в исходниках.
Лиды и апрувы ещё не импортируются; следующий шаг — пилотная сверка реального
ответа API и статусов одной кампании. Настройка кампаний/токенов и даты опубликованы
08.10.2026 на рабочем сайте. Общий API-ключ, токены, переопределение и проверка подключения
также опубликованы. Проверка — только чтение API, без импорта лидов.
Последняя резервная копия: `/root/domonetka-backup-20261008-personal-sessions`.


Сессии входа хранятся в SQLite (только SHA-256 токена) и переживают перезапуск сервиса.
Cookie HttpOnly, SameSite=Lax, Secure на HTTPS, срок 30 дней. При активности срок
продлевается не чаще одного раза в сутки. Выход завершает текущую сессию; смена
пароля, роли или отключение учётной записи отзывает все её сессии. После перехода
со старого хранения в памяти нужно один раз войти заново.

## OpsVault SSO

Хост-адаптер, атомарное связывание и проверки доступа описаны в [docs/OPSVault_SSO.md](docs/OPSVault_SSO.md). SSO 0.1.2 включён в production для пилота konst ↔ KONST; discovery, три серверных API и сохранность владельцев проверены. После явного связывания сохраняется локальный пароль, а реквизиты отправляются в зашифрованное хранилище OpsVault. Оба способа входа проверяют центральное разрешение. Реальное связывание и последующий вход ожидают действий владельца. JIT включён для новых пользователей с явным разрешением на сервис в OpsVault. Существующие admin и dima зарезервированы для адресного связывания с karlmichael и DemiGO; автоматическое создание дубликатов для них запрещено. Существующий аккаунт сначала связывается из локальной сессии, чтобы сохранить его ID и владельцев данных.
