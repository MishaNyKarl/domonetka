# Контракт модуля статистики

## Подключение точного API Binom

Контракт сверён с `docs/BINOM_REPORT_CONTRACT.md`. Готовый адаптер:

```js
const table = DomonetkaReport.createBinom({
  root: document.getElementById('report'), userId: state.me.id,
  streamId: () => selectedStream,
  syncUserId: () => currentStream()?.owner_id,
  onLocalPeriodChange: async period => { reportPeriod = period; await refreshLocalState(); },
  localData: () => ({offers: state.offers, variants: state.variants,
    streams: state.streams, period: reportPeriod}),
  onError: error => toast(error.message)
});
await table.ready;
// После смены потока и загрузки местного API:
await table.refresh(reportPeriod);
// При выходе: table.destroy();
```

createBinom загружает /api/binom/report, применяет динамический каталог через setColumns, разворачивает metrics и сырые пары статусов, сохраняет null и сообщает precision_warnings. Точные итоги выбранного периода рассчитывает Binom; модуль их не пересчитывает из daily. `pending_jobs` со статусами queued/running включает состояние обновления и продолжает опрос даже при пустых rows. Числовые поля каталога используют decimals; известные CR/ROI/lander_ctr — процент. Неизвестный format не интерпретируется вслепую как валюта/процент. rows используются отдельно от daily: суточные снимки не добавляются к агрегатам. Местные показатели присоединяются только при совпадении явно переданного localData.period с period отчёта. Местные вариации без импортированных строк остаются видимыми с отсутствующими метриками Binom. createBinom дополнительно фильтрует localData offers/variants/streams по выбранному streamId; переданные напрямую в adaptBinom данные нужно фильтровать вызывающей стороне. Для отдельного дневного представления интегратор может передать adaptBinom({...payload, rows:payload.daily}, localData), присоединив местные дневные показатели отдельно; адаптер не повторяет итог периода по дням.

Ручная кнопка отправляет POST /api/binom/sync {}, ждёт только ответ запуска 202, затем опрашивает отчёт каждые 5 секунд во время running/queued. Последний хороший снимок остаётся в таблице. Ошибки/last_attempt и last_success показываются; работающий импорт блокирует повторную кнопку. syncUserId необязателен для явно выбранного владельца администратором, принимает ID или функцию, которая вычисляется непосредственно перед запуском; userId используется только для идентичности текущего пользователя. Поля next_due и job_id не выведены как пользовательские метрики. Ошибка фонового GET вызывает onError и повторный опрос, пока интерфейс не уничтожен. refresh защищён от устаревших ответов. Начальная ошибка ready должна быть перехвачена интегратором.

adaptBinom(payload, localData) доступен отдельно и возвращает {rows, columns, period, summary:[], sync}. Итоги не вычисляются из разнотипных scope; интегратор может добавить проверенные summary выбранного среза. Для server callbacks по умолчанию используется fetch с same-origin credentials. При выборе даты createBinom сначала ожидает onLocalPeriodChange(period), затем получает Binom GET. Для совместимости при отсутствии onLocalPeriodChange использует options.onPeriodChange. Hook не вызывается при фоновых опросах или прямом refresh; интегратор должен обновить местные данные перед прямым refresh. Готовый createBinom безопасно скрывает местные числа при несовпадении периода, но сам не знает endpoint местного API.

Модуль готов для интеграции, но не подключён к admin.html/admin.js и не опубликован. Файлы: `public/report-table.js`, `public/report-table.css`, демонстрация `public/report-preview.html`. Не меняет БД, трекер, API или сущности баннеров. Демонстрационные числа находятся только в preview.

## Подключение

Подключить CSS и JS, добавить контейнер. Создать один экземпляр после установления личности пользователя; при logout/user switch вызвать destroy и создать другой. Дождаться ready перед установкой пользовательского вида.

```js
const table = DomonetkaReport.create({
  root: document.getElementById('report'),
  userId: state.me.id,
  loadPreferences: async () => /* получить вид текущего пользователя */ null,
  savePreferences: async preferences => { /* сохранить вид текущего пользователя */ },
  onPeriodChange: async ({from, to}) => {
    // '' означает открытую границу. Запрос UTC, границы включительно.
    // Получить отчёт; при ошибке throw. После успеха table.setData(...).
  }
});
await table.ready;
table.setData({rows, summary, sync, period: {from: '', to: ''}});
```

По умолчанию модуль использует GET/POST /api/report/preferences с JSON {preferences}; сервер определяет владельца по сессии. Callback load/save необязательны. Только явный localPreferences:true включает локальное сохранение для автономного прототипа. Не передавать секреты в callbacks, rows, summary или sync. savePreferences вызывается последовательно; сбой отображается, изменения остаются в текущем интерфейсе. Не использовать частичные callback пары.

## Строка и достоверность

Одна строка — одна заранее определённая сервером сущность отчёта, например вариация за период или вариация за UTC-день. Не смешивать агрегат и его суточные строки в одном наборе. Модуль не суммирует строки и не рассчитывает лиды, CR или статусы; сервер/адаптер отвечает за фильтры и знаменатели.

Поля плоские, их ID доступны в DomonetkaReport.columns:

- identity: scope, stream, banner, variant, affiliate_name («Партнёрка»), affiliate_id, title, description, image, active.

affiliate_id/affiliate_name берутся из строки серверного отчёта; для местных вариаций без импорта — из баннера/привязки, если доступны. Обе колонки доступны в группе «Баннер и вариация», скрыты по умолчанию. Категории approved/pending/rejected/unknown/approval_rate возвращает сервер по выбранной партнёрке владельца потока; интерфейс не угадывает их из сырых статусов. Управление партнёрками и трекерами входит в раздел «Конфигурация» интегрирующего кабинета, а не в окно вида таблицы.
- local: visitors, impressions, local_clicks, local_ctr.
- binom: campaign_id, clicks, unique_clicks, bots, lander_views, lander_clicks, lander_ctr, leads, cr, cost, revenue, profit, cpc, epc, roi.
- statuses: approved, rejected, pending, unknown, approval_rate, lead_status.
- events: event_1 … event_30.
- technical: day, imported_at, import_status, import_error.

`clicks` — клики Binom; местное `v.clicks` нужно явно преобразовать в `local_clicks`. `campaign_id` — Campaign ID баннера, не Offer ID Binom. Visitors относятся к потоку: не размножать и не суммировать по вариациям. Проценты передаются в процентных пунктах: 4 означает 4%, а не 400%. День — YYYY-MM-DD UTC; timestamps — ISO с Z/offset. Денежные значения отображаются без символа валюты: сервер должен согласовать валюту; нельзя суммировать разные валюты. `active` — boolean.

`scope` отображается по умолчанию и в каждом встроенном пресете: campaign → «Вся кампания Binom», attributed → «Трафик витрины», variant → «Вариация витрины». campaign включает немаркированный трафик. attributed требует одновременно dm_source=domonetka и совпадающих dm_flow/dm_offer; variant дополнительно совпадающую dm_variant. Промежуточные строки дерева отчёта не складывать с листьями. Для всей кампании местные показатели витрины missing, если они не описывают тот же срез. В итогах указывать срез явно; не складывать campaign/attributed/variant.

Значение может быть скаляром или объектом `{value, state:'ok'|'missing'|'error', error?}`. undefined/null/missing → «—»; 0 → «0»; error → «Ошибка» с пояснением. Статусы до подтверждения схемы передавать missing, а не 0. `unknown` — подтверждённое количество лидов с нераспознанным статусом, не замена отсутствующих данных. Сырые статусы new/payout/reject показывать отдельными динамическими колонками; не интерпретировать как semantic approved/pending/rejected до настройки словаря. Для устаревших подтверждённых значений использовать state ok и явное сообщение sync, дату последнего успеха. При частичном импорте нельзя выдавать частичные суммы как полные: summary.value=null, пояснение summary.help.

`summary`: массив `{label, value, help?}` с уже форматированными значениями (null → «—»). `sync`: `{label, lastSuccess, error}`; label передаётся на русском из адаптера и описывает актуальность отчёта. Не показывать сырые ответы API и секреты в error. `period` необязателен и синхронизирует date inputs; обработчик периода должен получать данные и вызывать setData после успешного запроса. Все строки должны уже соответствовать разрешённым потоку, владельцу и диапазону.

## Расширение реальными колонками Binom

Передать options.columns: массив `{id, label, group, type, visible, help, decimals?}`. Типы: number, decimal, percent, text, boolean, image, datetime. decimals 0–10 задаёт максимальное число знаков. Для встроенных ID можно уточнить метаданные тем же ID (label/type/decimals); поля, которые не переданы, наследуются. Новые группы через options.groups: `[['group_id','Название']]`; для нового поля обязательно указать существующую или новую группу. Все реально доступные числовые поля кампании из импортного контракта следует регистрировать таким образом, даже если они по умолчанию скрыты. Адаптер каталога /columns/report преобразует key→id, name→label, decimals→decimals; format→type только по проверенной схеме значений format, не угадывая процент по имени. Типы/значения колонок необходимо сверить с адаптером реального импорта: встроенный список не утверждает доступность каждого поля в API конкретного пользователя. Для сохранения группировки не менять group встроенного поля без необходимости.

## Предпочтения и поведение

JSON version 1: order (ID колонок), visible, groups (порядок групп), hiddenGroups, sections (summary/table/sync), hiddenSections, sort {id,dir}, presets [{name,view}]. Невалидные ID удаляются, новые поля добавляются скрытыми. Пресеты ограничены 20; имя до 60 символов через UI. getPreferences возвращает копию; setPreferences нормализует и сохраняет; destroy очищает интерфейс.

Колонки перемещаются внутри группы, группы перемещаются целиком. Настройки представлены checkbox и кнопками вверх/вниз: доступны на телефоне и клавиатуре. Стандартный вид возвращает колонки, группы, разделы и сортировку; пользовательские пресеты сохраняются. Поиск идёт по всем текстовым полям, включая скрытые. Сортировка стабильная, missing/error всегда в конце; 50 строк на страницу. Липкий заголовок внутри прокручиваемой таблицы, на мобильном горизонтальная прокрутка с сохранением табличного сравнения. Изображения допускают только HTTP(S). Все текстовые значения выводятся textContent.

## Интеграция текущего местного API

Объединить state.variants с state.offers/state.streams по постоянным ID. Поля variation: banner=offer.name, variant=variant.id (или человекочитаемое имя), title/description/image из variant, active=variant.active, impressions=variant.impressions, local_clicks=variant.clicks; local_ctr вычислять только при известном знаменателе и ненулевых показах. При нулевом знаменателе CTR missing. Binom поля пока missing. Summary получать отдельно, visitors показывать один раз для выбранного потока. Не подставлять `|| 0` для отсутствующих метрик. Параллельное обновление отчётов необходимо защищать от устаревших ответов в интегрирующем коде (последний выбранный поток/период должен побеждать).
